# 能力边界与可选增强

## Markdown 能约定什么

它能给 Agent 提供可重复读取的说明、明确事实入口、保留任务交接。效果依赖 Agent 是否读取、理解并遵守说明。文件本身没有权限强制、并发控制或自动执行能力。

本仓库不是记忆数据库，也不提供模型调用、跨对话 API、消息转发、定时任务、秘密管理、Git 自动推送或冲突合并服务。

## 想加自动同步时

先确认宿主提供哪些受支持能力，并限定执行者与写入范围。不要把私人实践中的命令、账号、进程或授权原样搬到另一台机器。

一个需要另行实现和验证的同步流程可以是：记录待处理决定 → 通知 → 接收方核对真实来源与权限 → 写回允许的位置 → 读回 → 返回结果。

其中至少要测试通知失败、重复通知、文件写完后中断、来源过期、并发修改和缺少权限。不同状态应分别记录；没有结果时不能无限重试或自动扩大权限。

自动同步是可选增强。本公开版本只提供决定记录模板，不实现上述流程，也不沿用私人环境的测试结果作为本仓库的验收结论。

## 代码地图与 GEB

分层代码说明可以帮助定位，但不能保证说明永不过期，也不能代替测试。项目小就少写，复杂模块按需补。地图、交接和用户决定应互相引用，避免维护三份同样的事实。

这个公开模板的组织方式来自个人实践；分层代码地图吸收了 GEB 相关公开方法。不主张独创这些通用思想，也不把任何社区项目称为唯一官方标准。
